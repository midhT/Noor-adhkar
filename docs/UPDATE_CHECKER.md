# Naseem public update checker

Naseem checks the public `midhT/Naseem-public` release feed without a GitHub token. It compares the published semantic version and Android build number with the app's embedded `naseem-version` and `naseem-version-code` values. Same-label 4.1.0 builds are therefore detected when the numeric build increases. The checker uses a cache-busted `no-store` request to the public `release.json`, then falls back to GitHub's Contents API if the raw feed is unavailable. It checks automatically on launch (after the initial UI settles) and when connectivity returns, and exposes **Settings → About Naseem → Check for updates** for a manual check.

When a newer release is found, Naseem displays an in-app banner with the direct APK asset and release-notes links. On Android, it schedules one local notification per newly detected version only when notification permission is already granted. The user dismisses the banner or notification and chooses whether to download and install. Android remains responsible for the final package-install approval; the app never silently installs an APK.

The release workflow publishes `app-release.apk`, `app-release.apk.sha256`, and the SHA-256 value plus checksum URL in `release.json`. The updater opens the official APK in the system browser; Android then presents its normal install/update confirmation. This is not a silent installer. The package ID, original CI signing secrets, and monotonically increasing Android versionCode must remain unchanged/valid for an in-place update. The download/install flow still requires physical-device verification on the target phone.

The M2 Playwright suite is a returning-user/navigation suite. It seeds the onboarding-complete key in its isolated browser context. First-launch onboarding and persistence remain covered separately by `tests/test_ui_logic.cjs`.
